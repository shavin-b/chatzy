# Chatzy Firebase migration plan

Status: prepared only. Existing order-flow-34826 configuration remains active. No target project ID or credentials have been fabricated. Project IDs cannot be renamed.

## Manual resources
1. Owner creates a uniquely available Chatzy project in Firebase Console, chooses Firestore region deliberately, enables billing as needed, Auth providers, Firestore, FCM, APIs, authorized web domains and budget alerts. Configure Analytics only after deciding consent/disclosure requirements.
2. Register Android package **com.orderflow.autoresponder** with genuine signing SHA fingerprints. Download google-services.json; keep the current app/google-services.json for normal builds. An isolated Chatzy build workspace may use app/src/debug/google-services.json or app/src/release/google-services.json. Never use applicationIdSuffix or change the package. Do not copy target credentials into the primary working environment until cutover approval.
3. Build with `-PexpectedFirebaseProjectId=ACTUAL_PROJECT_ID`. Google Services processing validates package and, when set, expected project. Missing/mismatched values fail without printing credentials. Configure separate CI workspaces for legacy and Chatzy; source-set overrides take precedence over app-level configuration.
4. Register a genuine Web app; copy its values into ignored .env.local or controlled CI env, from .env.example. Match VITE_COMMAND_API_BASE_URL, authDomain and authorized domains. VITE_* is public; never include a service-account key. Existing local env is intentionally untouched. No default alias was changed in .firebaserc.
5. Use newly rotated, least-privilege server credentials. Supply FIREBASE_PROJECT_ID/ALLOWED_ORIGINS as explicit Worker bindings, and FIREBASE_SERVICE_ACCOUNT_EMAIL/PRIVATE_KEY through Wrangler secrets or ignored .dev.vars locally. Existing wrangler.jsonc explicit legacy binding/name are retained for the legacy environment; copy wrangler.chatzy.example.jsonc into an ignored local deployment configuration, fill genuine target bindings and review its separate Worker name before an authorized deployment. No fallback to the legacy project remains in executable Worker source.
6. Functions use Firebase Admin ADC from the deployed project. Deploy only with explicit `--project ACTUAL_PROJECT_ID` after approval. Preserve us-central1 callables, names, payloads and roles. CLI/Functions runtime should match the declared Node 20 engine; local checks ran under Node 24 and do not prove Node 20 runtime compatibility.

## Backup, Auth, database, and cutover
- Inventory all root collections and subcollections. Document source document counts, Firestore field types, subscription expiries, device IDs, admin UIDs/roles, indexes and rules. CHATZY_DATABASE_SCHEMA.md is the source-code contract, not a live production inventory.
- Treat the supplied private key as compromised: revoke it in IAM, investigate audit logs and rotate dependent runtime secrets. Do not use it for exports. Use operator ADC/workload identity and an access-controlled backup bucket.
- With explicit production authorization, perform a managed Firestore export to a new protected backup prefix. Firestore export/import requires billing and bucket/service-agent permissions. Use the official export/import and move-data guides linked below. Do not run import against the old project or a nonempty target without a reviewed collision report: matching target IDs are overwritten by import.
- Export/import Firebase Auth separately, preserving UIDs and password hashes/parameters through the documented Auth tooling. Treat the Auth export and hash parameters as secrets; never commit them. Firestore export does not copy Auth users, rules, indexes, secrets, service accounts, domains or console settings. admins/{uid} must match the migrated Auth UID. Existing sessions require fresh authentication in the new project.
- Import into an EMPTY isolated target; preserve IDs and data types (timestamps versus epoch ms), nested collections, roles, expiries, audit/history records. Deploy reviewed indexes separately. Copy settings without overwriting business configuration from code defaults.
- Validate under a maintenance window/write freeze or other reviewed reconciliation protocol. Export is not a cross-service transactional snapshot. Freeze subscription/admin command writes for final reconciliation; legacy devices continue heartbeats, so account for those explicitly. Do not silently ignore changed expiry/lock/role fields.
- Read-only manifests: after obtaining read-only ADC, `node admin_web/functions/scripts/firestore-manifest.cjs --project ACTUAL_SOURCE_ID --output ABSOLUTE_NEW_SOURCE_MANIFEST_PATH`; repeat against target, then `node admin_web/functions/scripts/firestore-manifest.cjs --compare SOURCE_MANIFEST TARGET_MANIFEST`. Install Functions dependencies first. The script paginates, recurses subcollections, preserves field types in hashes and compares counts and per-field hashes. It never imports or changes remote data. Manifests include document paths and field hashes; store outside Git with restricted access. Not a substitute for a backup. Compare during a stable window; live mutable telemetry will differ. Include unexpected collections, not only the seven known ones.
- Prove admin authentication/roles, charts, search/filter, subscription extension/custom duration/history, real-time monitoring and LOCK/UNLOCK/SYNC with acknowledgement on test devices. Verify Cloud Functions alternative separately if used. Do not replay historical PENDING/SENT commands into enrolled devices; explicitly reconcile command state with the owner.
- FCM registration tokens are project/sender-bound. Copied old tokens are historical data only until the upgraded client obtains and uploads a target-project token. Preserve the cached OF- ID and local Room/preferences. DeviceManager initialization already uploads the active FirebaseMessaging token. Validate token renewal on an upgrade without clearing app data. Old binaries remain connected to the old project; a fleet cannot be switched by changing the web env alone.
- Pilot a signed same-package upgrade on backed-up test devices, then an approved small cohort. Reconcile subscriptions/locks changed in either environment during coexistence. Keep old services operational and use the rollback guide. Separate branding release from Firebase cutover to minimize customer risk.
